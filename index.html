Open Memory Format

Your memories, in files you own.

OMF is an open format for a life's record — journal days, notes, and the people and places in them — stored as plain Markdown files in a folder you control. Human-readable, app-agnostic, yours forever.

Plain files

A vault is just a folder of Markdown and a little JSON. No database, no lock-in, no proprietary blob. Back it up, grep it, edit it in any editor.

👁

Human-readable

Open any file and it reads like a note, not a data dump. YAML fields on top, your words below. Legible in fifty years.

🔗

App-agnostic

Any app that follows the spec can read and write the same vault. Move between apps — or take your data and leave — without an export step.

What a file looks like

A journal entry is a Markdown file.

The date lives in the filename. An optional # heading is the title; everything after is the body.

[[wikilinks]] connect a day to the people and places in it, and #tags group days and notes — the same syntax Obsidian understands.

People and places are files too.

One person or place per file. Structured fields go in YAML frontmatter; free notes go in the body.

A link's label, like (home), says how the two are related, and the other file links back.

Built on what you already know

Not a new syntax — a profile of three familiar ones.

  • CommonMarkStandard Markdown for every file body. Nothing bespoke to parse.
  • YAMLFrontmatter for structured fields — strict YAML, valid everywhere.
  • [[wikilinks]]Obsidian-compatible links & embeds for cross-references.
